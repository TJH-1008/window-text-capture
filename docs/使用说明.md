# 使用说明

## 环境

- Windows 10 / 11 x64，系统自带 PowerShell 5.1。
- 采集小程序需要本机已安装并登录微信，并且已打开目标小程序。
- 发行版不需要 Python、Node.js 或 Office；源码版需要 Python 3.10+（含 tkinter）和 Pillow。

## 安装与升级

**发行版**：解压 `WindowCapture_<版本>_便携版.zip` 到有写权限的普通文件夹，双击 `启动采集器.cmd`。
不要在压缩包预览里直接运行。程序默认在自身目录的 `采集数据` 读写，可以在右侧“更改保存目录”换位置。

**升级**：关掉旧程序，把升级包里的 `WindowCapture_<版本>.exe` 与 `启动采集器.cmd` 复制进旧目录；自定义对照表保留。需要新默认表时，从便携版单独取出并先备份旧表。
旧目录里的 `采集数据`（原文、任务进度、已导出结果）不会被覆盖或迁移。

**源码**：

```powershell
python -m pip install pillow
python app.py
```

## 采集：按商场清单

1. 点“导入清单”，选择 xlsx 或 UTF-8 CSV。
   - 原始数据库（含 `成都市综合体原始清单` 工作表、有 `来源/行政区域/项目名称` 列）会按来源精确筛选，
     默认只保留 `商务局`（可在 `roster.py` 的 `SOURCE_VALUE` 改）。
   - 普通清单需要有 `商场名称` 或 `项目名称` 列，可选 `行政区域`、`地址`、`搜索别名`。
     有 `来源` 列时同样按来源筛选，没有则全部导入。
2. 清单页单击任意一行，点“从选中项往后采集”，从该行处理到末尾；单行要重采，点“重试选中项目”后再从该行开始。
3. 采集过程中清单会自动定位到当前项目；点停止、切走窗口、达到滚动上限都会安全中断并保存已有内容。
4. 断点写在 `采集数据/清单任务/`，重新导入同一清单会恢复状态。

## 采集：单次

在微信里手动把页面滚到目标位置，点“只读取当前内容”，一次保存当前已加载且可访问的文字。
适合抽查、补采，或页面很轻、不需要自动滚动的情况。

## 采集：通用窗口

在“采集模式”选“通用窗口文本”，刷新窗口后选浏览器、微信聊天窗口或其他软件，填本次名称后采集。
通用模式始终保留沿途快照，不判断“到底”，也**禁用**商场业态转换（已有通用记录在批量转换中会记为“不适用”）。

> 自动滚动会激活目标窗口。多个滚动区域时滚轮可能落错区域：可以先手动滚动，再用“只读取当前内容”。

## 每次保存了什么

| 文件 | 内容 |
| --- | --- |
| `当前文档文本.txt` | 最后一次快照的当前文档文字，方便直接看 |
| `原始页面文本.txt` | 最终快照所有非空文档原文，按分隔符连接（框架文档会重复包含子文档，不能直接按行数商户） |
| `capture.json` | 窗口标题、句柄、时间、文档、底部提示、快照数、限制说明 |
| `raw-0000.json`… | 每次滚动前后的完整快照，用于恢复虚拟列表里已消失的文字 |
| `滚动文本快照.jsonl` | 全部快照的行式合集，便于二次处理 |
| `窗口截图.png` | 尝试保存最终截图；失败不影响文本 |

## 到底与完整性

- 检测到“已经到底 / 没有更多了 / 暂无更多 / 已显示全部”只表示**当前文档**包含底部提示，
  不代表与平台主页显示的数量一致。
- 连续 5 次文本不变会停止并标记“底部状态未确认”：可能到底，也可能滚动未生效或网络慢。
- 快速模式只保存最终文本，虚拟列表可能只留末页；需要沿途内容时取消该选项。
- 自动滚动默认最多 120 步（可调 1–500），每步等 1200 ms（可调 400–5000）。

## 批量整理 Excel

1. “批量 Excel”页选输入：默认用上方保存目录，也可“选择目录”或“ZIP / JSON / TXT”多选。
   ZIP 直接读取，不解压到别处。单文件 >128 MB、ZIP 解压后 >512 MB 会提示分批。
2. 需要时“Excel 模板”选含 `品牌明细` 工作表的 xlsx，程序只读表头，不复制样式/公式/宏/数据。
3. 点“整理并导出”。结果在 `<保存目录>/Excel结果/批量业态明细_时间_随机编号/`。

默认 11 个字段：`数据季度 / 项目编号 / 项目名称 / 品牌名称 / 楼层 / 楼层来源 / 四大业态--更细划分 /
细分业态 / 是否奢侈品 / 经营状态 / 官网链接`。

每份明细的工作表：

| 工作表 | 用途 |
| --- | --- |
| 品牌明细 | 主表，一行一家 |
| 待复核记录 | 名称截断、楼层不明、项目边界不清、筛选未确认、数量差异等 |
| 采集说明 | 本次采集的口径、对照表信息、命中率、边界说明 |
| 记录来源 | 每条记录对应的原文片段与快照/文档/行号 |
| 业态映射 | 平台原文 → 细分业态 → 标准业态，逐条标出匹配方式 |
| 业态待补清单 | 未命中的细分业态 + 建议动作 + 判定依据（无未命中时不生成） |
| 原始文本 | 分块保存的原文，供追溯 |

批次级还会输出 `批次索引.xlsx`、`批次索引.csv`、`批次报告.json` 和每份明细的结构化 `.json`。
批次索引记录本次耗时、模型 API Token=0、费用=0（只统计本机转换，不含前期采集、开发和人工整理），
以及使用的对照表位置、识别方式、指纹、标准业态清单和跳过原因。

## 合并与命名口径

- 以采集文件夹名作为商场名，自动去掉程序生成的时间戳前缀；同名不同楼层分别保留。
- 同一次采集的滚动快照，只按“店名 + 楼层原文 + 分类 + 位置标签”完全一致来合并；
  同一快照出现多条完全相同记录时保留并标待核。
- 标签只是存档名，不等于平台已确认的项目身份；没有匹配到主页身份时会标“归属待核”。
- 导出只新建结果文件，从不回填或改写原始采集目录与模板。

## 命令行

```powershell
# 采集单个窗口一次
WindowCapture_1.5.0.exe --capture-window 123456 --profile general --label 测试页面 --output D:\采集数据

# 通用模式默认向上滚动
WindowCapture_1.5.0.exe --profile general --scroll-direction up

# 批量整理（不弹界面）
WindowCapture_1.5.0.exe --batch-import D:\采集数据\captures --excel-output D:\结果 --mapping 业态对照表.csv

# 自检
WindowCapture_1.5.0.exe --smoke-test --smoke-report smoke.json
```

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 窗口列表里找不到小程序 | 先在小程序里点一下页面，再点“刷新窗口”；列表取的是可见顶层窗口 |
| 只读到标题或空白 | 该页面可能没暴露可访问性文本；浏览器可尝试用 `--force-renderer-accessibility` 启动后重试 |
| 导出条数明显少于页面显示 | 页面可能是虚拟列表，只保留末页；关掉快速模式重采，或分楼层采集 |
| 业态大量落“其他/待复核” | 看 `业态待补清单`，按建议动作往对照表补行，或改用最新的那份表 |
| 提示“多份对照表内容不一致” | 只保留一份主表，或在界面里“选对照表”固定使用某一份 |
| 升级后清单进度没了 | 进度按清单文件内容+保存目录识别；把保存目录指回原来的 `采集数据` |
