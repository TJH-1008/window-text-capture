# 设计约定

这份文档记录"改代码时要守住的边界"，避免界面上好看、行为上退化。

## 技术形态

原生 Windows Tk / ttk 桌面程序，**不要替换成 Web 套壳**。所有界面元素用标准库 tkinter + Pillow 渲染，
图标与封面由 `build_assets.py` 程序化生成（不引入外部图片素材），滚动条、磨砂层、按钮状态都在本地实现。

## 视觉契约

- 近白底 `#FAFAFA`、白色面片、`#D9D9D9` 发丝级描边；正文 `#262626`、次要 `#626262`、克制的绿 `#35A82F`。
- 主操作用黑底白字；导航常态无框、悬浮浅绿、选中带绿色标记；键盘焦点必须有可见反馈。
- 滚动条去掉两端箭头，保留原生拖拽/翻页/滚轮语义，滑块 9px 圆角并随 DPI 缩放。
- 标志为「深色圆角底 + 白色窗口框 + 柠檬绿捕捉点」，左侧标志、窗口图标、任务栏图标、EXE 图标共用一套
  几何生成器（`brand_icon.py`）；≤24px 时去掉标题栏与窗口内小点，只留框、内容和捕捉点。
  PNG 1024px，ICO 含 16–256px 十档独立栅格化结果。
- 标题用强对比黑体 + 短绿下划线；中文用 Microsoft YaHei UI；表格保持高密度但可读，停止按钮始终可达。
- 1400×900：标题 120px、摘要 122px、操作区 154px、日志 96px，其余高度给任务表。
  紧凑窗口（<830px 高）隐藏摘要行并保留固定停止按钮。
- 批量 Excel 页的操作区**按内容实测高度**（模板提示与业态对照表提示都必须完整可见，不能被卡片裁掉），
  上限 232px，避免挤掉表格。按钮按「输入 / 配置」分组，两组之间加竖分隔线。
- 摘要卡的状态用三个带色圆点的胶囊表达（已保存/待确认/待采集），不要退化成一整句灰字。
  模板与业态对照表前的状态点：绿＝用自定义文件，灰＝走内置默认。
- 右侧设置栏顶部是磨砂标题层：局部栅格化 + 7px 高斯模糊 + 34% 淡绿，随滚动刷新。
  它是近似效果，不是浏览器 `backdrop-filter`；不得捕获桌面、不得拦截下层控件、空闲时不得持续轮询。

## 业态对照表契约（1.5.0 起）

- 标准业态只能来自表；代码里不得出现"允许值白名单"或"内置大类兜底"。
- 归并分两段：`平台原文 → 标准细分业态 → 标准业态`。内置别名/关键词只能产出**细分业态**；
  该细分业态不在表里时必须判为未匹配，不许套用内置大类。
- 表不可用时必须降级（跳过坏文件 → 下一份候选 → 内置四类）并如实上报，**不得让整批转换失败**。
- 多份表共存时以"位置优先、同位置取最新"选一份，并用内容指纹（细分业态+标准业态集合）判断是否真的冲突。
- 匹配结果必须逐条可追溯（业态映射表），未匹配必须给可执行建议（业态待补清单）。

## 未改动的受保护行为

以下行为属于既有契约，改动必须同步更新测试，不要顺手重构：

- 采集读取（`window_reader.ps1` / `generic_reader.ps1`）、队列调度与断点、ZIP 读取上限、
  通用模式限制、停止与失焦处理、Excel 输出格式与表名、命令行参数。
- 原文无损保存：不因导出而修改 `采集数据`，不覆盖同名结果目录。
- 平台标签只作存档名，不当作已确认的项目身份；没有证据的字段留空，不猜。

## 验证方式

```powershell
python -m unittest discover -p "test_*.py"   # 业务 + 原生控件 + 打包脚本
python verify_opendesign.py                  # 三个工作区 + 紧凑模式渲染与截图
```

- 单元测试覆盖：业态表编码/分隔符/坏文件/歧义、清单来源筛选、快照合并边界、楼层与业态解析、
  导航状态机、界面控件可见性与 1100/1400 两档布局。
- `verify_opendesign.py` 会断言：磨砂标题层在滚动起点可见、模板与业态对照表提示不被裁、
  日志能显示一整行、导航悬浮/选中/键盘焦点状态、紧凑模式停止按钮在窗口内。
- 屏幕尺寸不足以容纳高倍缩放窗口时，相关布局断言按实际情况跳过，不伪装通过。
