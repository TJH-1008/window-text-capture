## 二、业态映射这条线，一直是同一套写法

1.2.1 与 1.4.1 的 `excel_import.py` 里，`GROUPS` 完全一致：

```python
GROUPS = {
    "餐饮":     "西式快餐|茶饮果汁|烤肉自助|潮汕牛肉火锅|冒菜|……（36 个平台原始业态）",
    "零售":     "数码产品|眼镜店|超市便利|……（20 个）",
    "亲子儿童": "体适能培训|婴童理发|儿童乐园|儿童服饰|母婴用品|托班/托儿所",
    "休闲娱乐": "棋牌室|电玩城|健身房|瑜伽|网吧/电竞|……（20 个）",
}
DEFAULT_MAPPING = {细分业态: 标准业态 ...}          # 从上面四个列表展开
```

`load_mapping()` 的校验是：

```python
if group not in {*GROUPS, "其他/待复核"}:
    raise ValueError(f"对照表标准业态不支持：{group}")
```

也就是说：**标准业态只有这四个合法值，第四个大类必须叫“休闲娱乐”**。同时只按 `utf-8-sig` 读 CSV，`.xlsx` 参考表不读。

## 三、改表后批量转换失败，根因是三条

| 现象 | 直接原因 |
| --- | --- |
| 报“对照表标准业态不支持：娱乐”并整批失败 | 新表把“休闲娱乐”改成“娱乐”、“亲子儿童”改成“配套”，不在白名单内；`load_mapping` 直接抛 ValueError，整批 `batch_export` 中断 |
| Excel 另存的 CSV 读不出来 | 硬编码 `encoding="utf-8-sig"`，Excel 默认存成 GBK/ANSI 就解码失败 |
| `Excel模板\业态对照表_Excel参考.xlsx` 改了没反应 | 1.4.1 只读 CSV，XLSX 完全没有读取路径，说明文档里只能写“需另存为 UTF-8 CSV 覆盖根目录同名 CSV” |

还有一条隐性断层：**口径变了，名字也全变了**。旧表 83 行是“平台原始业态 → 四大业态”（面包蛋糕、面馆、瑜伽、量贩式KTV…）；新表 83 行是“标准细分业态 → 标准业态”（烘焙甜点、小吃快餐/简餐、运动健身、KTV…）。即使把白名单放开，旧代码里的 `DEFAULT_MAPPING` 仍按平台原始业态查找，新表里一个都对不上，结果会几乎全落“其他/待复核”——所以只放开校验是不够的，必须补一层“平台原始业态 → 标准细分业态”的归并。

## 四、1.5.0 的做法

1. **标准业态由表决定**：`BusinessMapping.groups` 直接来自表内出现的值，代码里不再有白名单。表里改成“餐饮/零售/娱乐/配套”，或“餐饮服务/零售/文娱/生活服务/住宿”，输出列跟着变。
2. **两种格式都读**：CSV（UTF-8 / BOM / GB18030 / UTF-16；逗号、分号、制表符；允许标题行）与 XLSX（任意工作表，表头含“细分业态”“标准业态”即可）。读 XLSX 用标准库解析 OOXML，不依赖 Excel、openpyxl。
3. **两段式归并**：`平台原文 → 标准细分业态 → 标准业态`。第二段一律查表；第一段依次用“表内精确 → 表内别名列 → 内置别名 → 内置关键词”，内置只负责认出“这是哪个细分业态”（面包蛋糕→烘焙甜点、瑜伽→运动健身），不负责给标准业态。
4. **表里没有就不猜**：内置归并指向的细分业态若不在表内，不套内置大类，直接进“业态待补清单”，并写明“补一行：细分业态=XX，标准业态取 本表可选值 之一”。
5. **位置优先 + 时间次之的自动识别**：程序目录 > 输出目录 > 数据目录；同一位置取 mtime 最新。CSV 与 XLSX 同名不同格式时用内容指纹（细分业态+标准业态集合）判断是否真不一致，避免“字节不同就报冲突”的噪音。
6. **绝不整批失败**：坏表跳过并记录原因，依次退到下一份可用表 → 内置四类业态；单个商场出错只影响那一条。界面底部常显“业态对照表：文件名（几类标准业态，几个细分业态）· 自动识别/手工指定”，悬停看完整识别说明；批次索引写位置、方式、SHA256 前 12 位、标准业态清单。
7. **输出可追溯**：每份明细带“业态映射”表（原文 / 归并到的细分业态 / 标准业态 / 匹配方式 / 记录数 / 说明），未匹配的另带“业态待补清单”（原文 / 记录数 / 建议动作 / 判定依据）。

## 五、原版本说明所载的真实数据验证（本次未复测）

- 数据：117 份真实采集记录（本地采集目录）。
- 表：你现在的 `业态对照表.csv` / `业态对照表_Excel参考.xlsx`（餐饮、零售、娱乐、配套，83 行 / 77 个不重复细分业态）。
- 结果：117 份明细全部生成、0 失败、约 32 秒；16 418 条品牌记录，命中 15 580 条（94.9%）。匹配方式：内置别名 13346、表内精确 1785、内置关键词 449。
- 838 条未命中全部是设施与住宿类：智能按摩空间 516、充电站/桩 73、经济型/高档型/舒适型/豪华型/民宿/酒店 92、停车场 38、更多购物场所 33、智能自助设施 22 —— 该表没有住宿、设施类口径，属预期结果，进待补清单即可。
- 改表实测：整表改名（餐饮→餐饮服务、娱乐→文娱、配套→生活服务）并新增“住宿”后，不改一行代码重新整理，`四大业态--更细划分` 列直接输出新口径；只改 CSV 不动 XLSX 时，程序取刚改过的那份。
- 打包实测：解压发行 zip → 自检（清单加载、图标与读取脚本齐全）→ 改 CSV 后跑 4 家 → 输出采用改后的表、0 失败。
- 自动化测试 113 项通过 112 项；跳过的是 `test_display_scale(scale=2)`——屏幕放不下 2 倍缩放窗口，改为按实际屏幕跳过，不再把环境限制算成失败。

## 六、还没解决 / 需要你定的

1. “其他”在娱乐、配套下各有一行，表内无法唯一定位，只能标其他/待复核。建议改写成“其他（娱乐）”“其他（配套）”。
2. 住宿（酒店/经济型/高档型/民宿）、设施（停车场/充电桩/按摩椅）要不要单独成类，需要按分析目的定口径；定了之后往表里加行就行，不用改程序。
3. 两张表同时存在时只取一份（程序目录优先，其次最新修改）。长期维护建议只留一份主表，另一份同步或删除。
4. 本次没有重做真实小程序窗口的现场采集验收，采集与界面逻辑沿用 1.4.1-OpenDesign.2；界面改动只涉及批量 Excel 页的提示高度。
